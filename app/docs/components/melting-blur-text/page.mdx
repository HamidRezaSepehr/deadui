Move the pointer across the preview. The characters nearest to it sag and
blur, then an SVG gooey filter on the container welds them back into one wet
silhouette. Every frame the pointer position is interpolated toward with
`inertia`, so the melt trails behind a fast flick instead of teleporting.

`effectRadius` is how far from that interpolated point a character reacts.
`blurSpread` sets both the drip distance (twice the spread) and the blur
radius on each character. `blurQuality` is the container filter's
`stdDeviation` — inverted on purpose, so `high` is a tight `4` and `low` is a
wide `10`.

## Usage

```tsx
import { MeltingBlurText } from "@/components/ui/melting-blur-text"

export function Hero() {
  return (
    <MeltingBlurText
      effectRadius={60}
      blurSpread={8}
      blurQuality="medium"
      inertia={0.15}
    >
      Hover over this text to melt it.
    </MeltingBlurText>
  )
}
```

The component sizes its own type as a display heading; pass `className` to
put it on your own scale.

## Props

| Prop            | Type                                | Default            | Description                                                                 |
| --------------- | ----------------------------------- | ------------------ | --------------------------------------------------------------------------- |
| `children`      | `string`                            | —                  | The sentence to melt. Split into one `<span>` per character.                 |
| `effectRadius`  | `number`                            | `60`               | Distance from the lerped cursor at which a character starts to melt.         |
| `blurSpread`    | `number`                            | `8`                | Drip distance (× 2) and per-character blur radius, in pixels.                |
| `blurQuality`   | `'low' \| 'medium' \| 'high'`       | `'medium'`         | Gooey filter precision: `high` → `4`, `medium` → `6`, `low` → `10`.          |
| `inertia`       | `number`                            | `0.15`             | Per-frame lerp factor, `0.05` (heavy lag) to `0.5` (near instant).           |
| `className`     | `string`                            | —                  | Merged over the base classes with `cn()`.                                    |

## Dependencies

- `framer-motion` — `useReducedMotion`
- `clsx` + `tailwind-merge` — `cn`

Ships one file: `melting-blur-text.tsx`.

## Performance

- The melt is computed in a single `requestAnimationFrame` loop and written
  straight to each character's `style.transform` / `style.filter`. React never
  re-renders during a sweep, so a forty-character sentence costs one component
  render total, not sixty per second.
- Character centres are cached from `offsetLeft` / `offsetTop` and refreshed
  only by a `ResizeObserver`. Transforms do not dirty layout, so the one
  `getBoundingClientRect()` per frame reads a clean box and forces no reflow.
- The loop parks itself once the pointer leaves and the effect has fully
  drained, so an idle page runs no work at all.
- The container-level gooey filter is applied only while the melt is active
  and removed as soon as it drains, so at rest the text renders through no
  filter at all — identical glyphs, zero cost, always fully legible.
- During the melt the filter composites the crisp `SourceGraphic` over the
  gooey silhouette, so letters stay sharp and readable instead of being
  burned away by the alpha threshold.
- The container filter region is expanded well past the default `-10% / 120%`
  box — a drip plus its blur always falls outside that, and the default region
  would clip it into a straight edge.

## Accessibility

- Under `prefers-reduced-motion: reduce` the animation loop never starts and
  the SVG filter is never applied. The sentence renders once as plain,
  static text.
- The character spans carry no roles or labels, so the split stays out of the
  way: assistive technology reads the original string as one continuous
  sentence.
- Each word is grouped inside an `inline-block whitespace-nowrap` run and only
  real whitespace stays a plain inline box, so a word can never break across a
  line — if it does not fit, the whole word moves to the next line. The melt
  is written to per-character transforms, so it never changes the layout it
  is painted on top of.
