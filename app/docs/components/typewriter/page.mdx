# Typewriter

A classic type-and-delete text animation wrapped around
[`typewriter-effect`](https://github.com/tameemsafi/typewriterjs), with
specialized control over the blinking cursor — its colour, width, height and
glyph are all props, forced onto the library's own cursor element without
touching its native blink animation.

Move any control and the sequence restarts with the new configuration. Set
**Loop** to `false` to watch a run finish with the text left on screen.

## Usage

### Single text

```tsx
import { Typewriter } from "@/components/ui/typewriter"

export function Example() {
  return <Typewriter text="Building interfaces that feel alive." />
}
```

A non-looping single string stays on screen once typed — it is passed to the
engine as a string, which the library never deletes.

### Looping array of strings

```tsx
<Typewriter
  loop
  delay={65}
  text={[
    "Design. Prototype. Ship.",
    "Type, delete, repeat.",
    "One component, endless text.",
  ]}
/>
```

Arrays type each entry in order, hold it, delete it and move to the next —
and with `loop` they cycle forever. Every cycle ends with a delete, which is
what keeps a looping single string from appending onto itself.

### Custom cursor

```tsx
<Typewriter
  text="Thick blue block"
  cursor="▋"
  cursorColor="blue"
  cursorWidth="4px"
  cursorHeight="1.2em"
/>
```

### Speed and completion

```tsx
<Typewriter
  text={["First", "Second"]}
  delay={120}
  deleteSpeed={40}
  onComplete={() => console.log("sequence finished")}
/>
```

`delay` is the millisecond gap between typed characters (`deleteSpeed`
defaults to it, so deletion keeps pace). `onComplete` fires once a
non-looping run drains its queue, or once per cycle while looping.

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `text` | `string \| string[]` | — | **Required.** The text to type. A single string types once and stays; an array types each entry in sequence, deleting between them. |
| `delay` | `number` | `50` | Milliseconds between typed characters. Also the default delete speed. |
| `deleteSpeed` | `number` | `delay` | Milliseconds between deleted characters. |
| `loop` | `boolean` | `false` | Restart the sequence forever instead of finishing after the last string. |
| `autoStart` | `boolean` | `true` | Begin typing on mount. |
| `cursor` | `string` | `"\|"` | The glyph rendered inside the cursor element. Any string — a pipe, a block character, an emoji. |
| `cursorColor` | `string` | `"currentColor"` | CSS colour applied to the cursor, e.g. `"blue"`, `"#ef4444"`. |
| `cursorWidth` | `string` | `"2px"` | CSS width of the cursor box. The glyph is clipped to it, so the value is authoritative. |
| `cursorHeight` | `string` | `"1em"` | CSS height of the cursor box, e.g. `"1.2em"`. |
| `onComplete` | `() => void` | — | Called when the sequence completes — once without `loop`, every cycle with it. |
| `className` | `string` | — | Merged onto the component's base `inline-flex items-center` root. |
| `...props` | `HTMLAttributes<HTMLDivElement>` | — | Spread onto the rendered element. |

## Dependencies

- [`typewriter-effect`](https://github.com/tameemsafi/typewriterjs) — the
  typing engine (listed in `registry.json`, so the CLI installs it for you).

## Performance

- All typing runs on the engine's animation-frame loop in the browser; the
  React tree renders once and never re-renders while the sequence plays.
- Cursor styling is one static `<style>` block per instance, scoped by
  `useId()` — several typewriters with different cursors coexist on one page
  without their rules colliding, and the block never touches the library's
  injected `Typewriter-cursor` keyframes.
- The engine injects its blink keyframes into `<head>` exactly once per page.

## Accessibility

- Under `prefers-reduced-motion: reduce` the sequence does not run: the first
  string is rendered statically, the engine is stopped before its first frame,
  and the cursor's blink animation is disabled while the cursor stays visible.
- The animation is decorative — the text lives in the DOM the whole time and
  nothing is communicated by the motion alone.
