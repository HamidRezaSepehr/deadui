# Orbiting Circles

Concentric rings that carry icons, images, or any React node around a center
point. The headline feature: **every orbiting item stays perfectly upright**
— its top always points at the top of the viewport — while the ring spins
beneath it, using pure CSS counter-rotation.

Watch closely as `radius` grows or `reverse` flips: the ring turns, but the

is the time for one full revolution, so lower is faster; `path={false}`
hides the track border.

## Usage

Orbiting Circles is three nested components:

- `<OrbitingCircles>` — the relative, full-size container.
- `<Orbit radius={…}>` — one ring. Handles the rotation animation and the
  visible track.
- `<OrbitItem angle={…}>` — one item on a ring (any React node: icons,
  images, SVGs, plain divs).

```tsx
import { OrbitingCircles, Orbit, OrbitItem } from "@/components/ui/orbiting-circles"
import { Heart, Star, Zap } from "lucide-react"

export function Planets() {
  return (
    <OrbitingCircles>
      <Orbit radius={120} duration={20}>
        <OrbitItem angle={0}>
          <Zap />
        </OrbitItem>
        <OrbitItem angle={120}>
          <Heart />
        </OrbitItem>
        <OrbitItem angle={240}>
          <Star />
        </OrbitItem>
      </Orbit>
    </OrbitingCircles>
  )
}
```

`angle` is measured clockwise from 3 o'clock: `0` is right, `90` is bottom,
`180` is left, `270` is top.

### Multiple rings with different speeds and directions

Nest any number of `<Orbit>`s. Give each its own `radius`, `duration` and
`reverse`, and add a center node as an ordinary positioned child:

```tsx
import { OrbitingCircles, Orbit, OrbitItem } from "@/components/ui/orbiting-circles"

export function SolarSystem() {
  return (
    <OrbitingCircles>
      {/* center */}
      <div className="absolute left-1/2 top-1/2 h-14 w-14 -translate-x-1/2 -translate-y-1/2 rounded-full bg-dead-red" />

      {/* inner ring, fast + counter-clockwise */}
      <Orbit radius={70} duration={10} reverse>
        <OrbitItem angle={0}><IconA /></OrbitItem>
        <OrbitItem angle={90}><IconB /></OrbitItem>
        <OrbitItem angle={180}><IconC /></OrbitItem>
        <OrbitItem angle={270}><IconD /></OrbitItem>
      </Orbit>

      {/* outer ring, slow + clockwise */}
      <Orbit radius={150} duration={30}>
        <OrbitItem angle={30}><IconE /></OrbitItem>
        <OrbitItem angle={150}><IconF /></OrbitItem>
        <OrbitItem angle={270}><IconG /></OrbitItem>
      </Orbit>
    </OrbitingCircles>
  )
}
```

### Hiding the track

Set `path={false}` on an `<Orbit>` to make its ring border invisible — the
items keep orbiting over an empty canvas:

```tsx
<Orbit radius={110} duration={18} path={false}>
  <OrbitItem angle={0}><Heart /></OrbitItem>
</Orbit>
```

## How the "upright icon" trick works

Keeping an item upright while it orbits is a **counter-rotation**, and it needs
three moving parts that stay in perfect sync:

1. `<OrbitItem>`'s outer div places the item on the ring with the static
   transform `translate(-50%, -50%) rotate(angle) translateX(radius) rotate(-angle)`.
   The leading `translate(-50%, -50%)` centres the item's box on the ring
   centre first — so the item's own centre lands exactly on the circle of
   `radius` — and the trailing `-angle` unwinds the placement rotation, so at
   ring-rotation 0 the item's local axes are already aligned with the viewport.
2. The ring rotates `0 → 360deg` over `duration` (`orbit-spin`,
   `linear`, `infinite`), carrying every item around the center.
3. **The counter-rotation:** `<OrbitItem>`'s inner div rotates
   `0 → -360deg` over the *same* `duration`, also `linear`, starting at the
   same time (`orbit-counter-spin`). Ring `+θ`, content `−θ`, and the two
   cancel at every frame: `−θ + θ = 0`.

```css
@keyframes orbit-spin {
  from { transform: rotate(0deg); }
  to   { transform: rotate(360deg); }
}
@keyframes orbit-counter-spin {
  from { transform: rotate(0deg); }
  to   { transform: rotate(var(--orbit-counter-target, -360deg)); }
}
```

For `reverse` (counter-clockwise) rings the counter target flips to
`+360deg`. This is a **keyframe-value change, not
`animation-direction: reverse`** — reversing the direction of a
`0 → -360` animation shifts its phase, so the two cancelling rotations stop
matching mid-cycle and the icon tilts. Changing the target sign keeps the two
rotations exact opposites at every frame in both directions. The keyframes
ship inside the component (an embedded `<style>`), so a CLI install is fully
self-contained.

The rings are centered with negative margins, and the whole component is GPU
compositor-driven (`transform` only) — zero JavaScript per frame.

| Prop       | Type                     | Default | Description                                      |
| ---------- | ------------------------ | ------- | ------------------------------------------------ |
| `children` | `React.ReactNode`        | —       | `<Orbit>` rings (and optional center content).   |

| Prop                | Type      | Default | Description                                       |
| ------------------- | --------- | ------- | ------------------------------------------------- |
| `radius`            | `number`  | — (required) | Ring radius in pixels.                        |

| `children`          | `React.ReactNode` | — | `<OrbitItem>`s on this ring.              |
| `className`         | `string`  | —       | Additional classes for the ring div.              |
| `...props`          | `HTMLAttributes<HTMLDivElement>` | — | Spread onto the ring div.              |

| Prop       | Type      | Default | Description                                       |
| ---------- | --------- | ------- | ------------------------------------------------- |

| `...props` | `HTMLAttributes<HTMLDivElement>` | — | Spread onto the wrapper.               |

## Performance

- Pure CSS — the ring and each item's content animate `transform` only,
  so every frame is composited on the GPU with no JavaScript.
- Because the counter-rotation runs a second animation per item, large rings
  of many items cost more compositor work; keep heavy rings under a few dozen
  items on mid-range hardware.
- The component ships its keyframes in an embedded `<style>`, so it carries
  no styled-jsx, Tailwind config, or `globals.css` requirement.

## Accessibility

- Under `prefers-reduced-motion: reduce` the animations stop entirely
  (`animation: none`) and the diagram falls back to its static layout: items
  still at their `angle`s, upright, on their tracks.
- The rings and items are decorative by default. Give your icons `aria-label`
  or use real text/`alt` on images when the visuals carry meaning, since
  screen readers will not describe the motion.
